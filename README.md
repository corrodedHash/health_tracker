# health_tracker

A Rust workspace for tracking workouts (weight, core, running) with a
Vite + React frontend and a Matrix bot for GPX ingest. Backed by Postgres
via SQLx with class-table inheritance for the exercise hierarchy.

See [`docs/base.md`](docs/base.md) for the architecture and design decisions.

## Layout

```
health_tracker/
├── crates/
│   ├── core   # domain types — zero I/O
│   ├── db     # SQLx repository + migrations
│   ├── auth   # OIDC PKCE flow
│   ├── web    # axum server, binary 1
│   └── bot    # matrix-sdk bot, binary 2
├── frontend/             # Vite + React + TS + shadcn/ui + echarts
├── migrations/           # SQLx migrations (Postgres-only)
├── config/
│   ├── default.toml       # checked-in config defaults (bot, no secrets)
│   └── default.toml.dist  # template with all options documented
└── .github/workflows/    # CI (test) + release pipelines
```

## Quickstart

### Prerequisites

- Rust 1.85+ (workspace uses `edition = "2024"`). The pinned nightly
  toolchain lives in `rust-toolchain.toml`; `rustup` picks it up
  automatically.
- Postgres 13+ (the migrations use `gen_random_uuid()`, `INTERVAL`,
  `BYTEA`, `TIMESTAMPTZ`).
- Docker — required to run the local Postgres, Dex, and Synapse containers.
  SQLite is intentionally not supported.
- Node 20+ and pnpm for the frontend (the repo pins `pnpm` via `mise` and
  `package.json`'s `packageManager` field).

### Build & test

```sh
cargo check --workspace
cargo clippy --workspace --all-targets -- -D warnings
mise run test
```

All tasks use `mise run` — see `mise tasks` for the full list. `mise run test`
auto-starts a Postgres container if one isn't running.

### Frontend

```sh
mise run frontend-dev     # Vite dev server, proxies /api -> http://localhost:3000
mise run frontend-build   # type-check + production build into frontend/dist
```

In production the axum server serves `frontend/dist` as static files
with an SPA fallback; the dev server proxies `/api` to `localhost:3000`.

### Configuration

Config is loaded by the [`config`](https://docs.rs/config) crate using
different sources per binary:

| Binary | Sources (lowest → highest priority) |
|--------|--------------------------------------|
| `health-web` | `HEALTH__*` env vars only |
| `health-bot` | `config/default.toml` → `config/local.toml` → `HEALTH_*` env vars |

Both use `__` for nesting (e.g. `HEALTH__OIDC__ISSUER_URL`). Note the
different prefix on the env-var layer: web uses `HEALTH__` (double
underscore after `HEALTH`), bot uses `HEALTH_` (single underscore).

A template with every option documented is at
[`config/default.toml.dist`](config/default.toml.dist).

#### `health-web`

| Required | Variable | Purpose |
|----------|----------|---------|
| ✅ | `HEALTH__DATABASE_URL` | Postgres connection string |
| ✅ | `HEALTH__COOKIE_KEY` | Hex-encoded 64-byte key (`openssl rand -hex 64`) |
| ❌ | `HEALTH__LISTEN_ADDR` | Default `0.0.0.0:3000` |
| ❌ | `HEALTH__STATIC_DIR` | Path to pre-built frontend `dist/` |
| ❌ | `HEALTH__FRONTEND_URL` | Frontend origin for CORS / redirects |
| ❌ | `HEALTH__COOKIE_SECURE` | Default `true` (`false` for local HTTP) |
| ❌* | `HEALTH__OIDC__ISSUER_URL` | OIDC issuer — set all four or none |
| ❌* | `HEALTH__OIDC__CLIENT_ID` | OIDC client ID |
| ❌* | `HEALTH__OIDC__CLIENT_SECRET` | OIDC client secret |
| ❌* | `HEALTH__OIDC__REDIRECT_URI` | OIDC callback URL |

#### `health-bot`

The bot reads `config/default.toml` (checked in) and `config/local.toml`
(gitignored, generated by `mise run ensure-synapse` for local dev).
All keys can be overridden via `HEALTH_*` env vars.

| Required | Env var / TOML key | Purpose |
|----------|---------------------|---------|
| ✅ | `HEALTH__MATRIX__USER_ID` / `matrix.user_id` | Bot Matrix user ID |
| ✅ | `HEALTH__MATRIX__PASSWORD` / `matrix.password` | Bot password |
| ✅ | `HEALTH__API__TOKEN` / `api.token` | Bearer token for the web API |
| ❌ | `HEALTH__MATRIX__HOMESERVER` / `matrix.homeserver` | Default `https://matrix.org` |
| ❌ | `HEALTH__MATRIX__SESSION_FILE` / `matrix.session_file` | Default `session.toml` |
| ❌ | `HEALTH__API__BASE_URL` / `api.base_url` | Default `http://localhost:3000` |

## Development

### Workflow overview

| Goal | Command | Auto-starts |
|------|---------|-------------|
| Full stack (web + OIDC) ¹ | `mise run dev` + `mise run frontend-dev` ² | Postgres + Dex |
| Web only (auto-login) | `mise run run-web` + `mise run frontend-dev` ² | Postgres |
| Matrix bot | `mise run run-bot` ³ | Synapse |
| Test suite | `mise run test` | Postgres |
| Refresh SQLx cache | `mise run regenerate-sqlx` | Postgres |

¹ With OIDC (Dex). Without OIDC, use `mise run run-web` (auto-login).

² Frontend and web server run in separate terminals.

³ The web API must already be running (either `dev` or `run-web`).

See `mise tasks` for the full list of tasks and their descriptions.

### Docker containers

Three containers are managed by helper scripts (started on demand, `--rm`):

| Container | Image | Port | Purpose |
|-----------|-------|------|---------|
| Postgres | `postgres:16` | `5432` | Database (always needed) |
| Dex | `ghcr.io/dexidp/dex:v2.42.0` | `5556` | OIDC provider for auth testing |
| Synapse | `matrixdotorg/synapse:latest` | `8008` | Matrix homeserver for bot testing |

### Local env overrides

Create `.mise.local.toml` (gitignored) to override env vars without
modifying `mise.toml`. See `.mise.local.toml` in the project root for a
template with all available options.
